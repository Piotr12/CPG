## The generator's output contract (binding for Phases 1 and 3)

`generateTestTenantDataset(config, today: string /* YYYY-MM-DD, UTC */): TestTenantDataset`, pure and deterministic. All quantities are decimal strings (the repo's `domain/quantities/decimal.ts` bigint micro-units for arithmetic — never floats for stock). All dates `YYYY-MM-DD`; every event carries `at: string`, an ISO-8601 UTC timestamp (the spec's "Times of day").

```ts
interface TestTenantDataset {
  today: string;
  anchor: string;          // first day of the current month
  historyStart: string;    // anchor − historyMonths
  setupDate: string;       // first day of the setup month (historyStart − 1 month)
  masters: {
    materials: { type: "raw" | "intermediate" | "finished"; description: string; baseUnit: string;
                 conversions: { unit: string; numerator: string; denominator: string }[] }[];   // ID order → 00000001…
    locations: string[]; customers: string[]; suppliers: string[];                               // names, ID order
    boms: { output: string; priority: number; validFrom: string; validThrough: null;
            components: { material: string; quantity: string; unit: string }[] }[];              // ID order → 00000001…
    planningParameters: { material: string; location: string; procurement: "make" | "buy";
            leadTimeDays: number; minimumQuantity: string; lotMultiple: string }[];
    safetyStockTargets: { material: string; location: string; effectiveFrom: string; quantity: string }[];
  };
  forecasts: { material: string; location: string; date: string; quantity: string }[];
  timeline: TimelineEvent[];   // chronological (by `at`), already cut at today: history + today's partial postings
  summary: Record<"customerOrders" | "shipments" | "goodsIssues" | "requisitions" | "purchaseOrders" | "goodsReceipts"
                  | "productionOrders" | "completions" | "openings" | "movements", number>;
}

type TimelineEvent =
  | { kind: "opening"; at: string; location: string; lines: { material: string; quantity: string; unit: string }[] }
  | { kind: "customerOrder"; at: string; key: string; customer: string; location: string;
      lines: { material: string; quantity: string; unit: string; requiredDate: string }[] }
  | { kind: "shipment"; at: string; key: string; order: string /* customerOrder key */; plannedDate: string;
      lines: { orderLine: number /* 0-based index into the order's lines */; quantity: string; unit: string }[] }
  | { kind: "goodsIssue"; at: string; shipment: string /* key */; lines: { line: number /* 1-based shipment line */; quantity: string; unit: string }[] }
  | { kind: "requisition"; at: string; key: string; material: string; location: string; quantity: string; unit: string; requiredDate: string }
  | { kind: "purchaseOrder"; at: string; key: string; supplier: string; location: string;
      lines: { material: string; quantity: string; unit: string; plannedDate: string; requisition?: string /* key */ }[] }
  | { kind: "goodsReceipt"; at: string; order: string /* key */; lines: { line: number /* 1-based */; quantity: string; unit: string }[] }
  | { kind: "productionOrder"; at: string; key: string; output: string; location: string; quantity: string; unit: string;
      plannedFinish: string; bom: string; revision: number }
  | { kind: "completion"; at: string; order: string /* key */; quantity: string; unit: string;
      components: { material: string; quantity: string; unit: string }[] };
```

Materials, locations, customers, suppliers and BOMs are referenced by the business ID they get on a fresh generation (`00000001`…, their index + 1). Documents are referenced by generator `key`s; the seeder maps keys to the IDs and line IDs the services return. Within the timeline, creations come in date order, so the services' sequential IDs ascend with time (R01).

Inclusion rule at `today`: every creation and posting dated **before** today is in the timeline; on today only the spec's explicit partial documents (partial shipment + issue, open shipment, partial receipt, partial completion) and nothing else. A partial posting dated today is capped at what the replay has available at that moment (a line with nothing available is dropped; a document left with no lines is skipped), so the replay holds on every day.

#### 1.2 Calendar and seeded random helpers

#### 1.3 Demand plan
- `demand-plan.ts`: `D(p, m)` with season × growth × noise; split over customers by weight, whole base units (≥ 1), export distributors rounded to whole pallets/cases and entered in that unit; customer orders per customer × plant × month with the spec's creation and required weekdays, partial-shipment rule (every ninth order).
- Tests from the spec's step 3.

#### 1.4 Supply plan
- `supply-plan.ts`: stock model per material × plant; safety targets (and the two later increases); opening balances; order-up-to production per made pair and month (completion bands, planned start/finish, creation on weekday 8 of the previous month); explosion over the priority-1 BOM; purchases per raw material × plant grouped per supplier × plant × month (receipt band, creation on weekday 2 of the previous month, hinge/lock supplier alternation, Poznań's bought shelves); variance (every 7th / 11th completion per plant) and waste (one zero-output completion per plant, seven months before the anchor); converted requisitions raising next month's quantity.
- Tests from the spec's step 4.

#### 1.5 Timeline and generator
- `timeline.ts`, `generate-dataset.ts`: dated events with times of day, band ordering within a day, the "as of today" cut, open-document rules (partials, open shipment, top-up orders, requisitions), forecasts; `generateTestTenantDataset(config, today)` returning the contract above.
- Tests from the spec's step 5.

#### 1.6 Ledger replay and limits
- `replay.ts`: replays the timeline over the openings (entered units converted to base through the catalogue's conversions); throws naming the pair on a negative balance and naming the limit on a breach; `generateTestTenantDataset` calls it.
- Tests: the committed config passes for every calendar day of a two-year window; mutated configs fail with the limit / the pair named.
