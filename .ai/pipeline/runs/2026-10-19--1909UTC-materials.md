## Goal

In each tenant the admin creates and edits materials: an eight-digit ID assigned in sequence per tenant, a type, a description, a base unit, an active flag, and exact conversions from other units. Every signed-in user views them, in the UI and through the API. An entered quantity converts into the base unit once, half-up to six decimals, without binary floats. Test is seeded with demo materials.

## Risks

## Deviations from the spec

- **The seed lives in `core/src/demo-data.ts`**, not `database.ts`: it builds a container, and `container.ts` already imports `database.ts`, so putting it there would make an import cycle.
- **`VERSION_CONFLICT` and `versionConflict()` moved to `http/errors.ts`** for the second versioned service; `versionSchema` moved from `validators/users/` to `validators/version.schema.ts`. Both were planned in #21's notes for this story.
- **The migration's `down()` drops `material_conversion` before `material`** (hand-reordered before the first push): the generated order fails SQLite's foreign-key check on a table with rows. A test rolls it back with rows present.
- **A reusable `ConfirmDialog` (`ui/backend/dialogs/`) and `orNotFound` (`app/src/routing/`)** were added: materials needed two more confirmations and two more "missing → not found" pages, and users/tokens and two tenant pages already had copies. The tenant pages now use `orNotFound`; the users and tokens dialogs are left as they are (no drive-by refactor).
- **The tenant home's "No business records yet" placeholder** became the Materials link, and `audit.test.ts` no longer expects the Test audit to be empty: the materials integration files write Test records first.
- **The Add conversion form shows a static formula** ("Alternate quantity × unit = base quantity × each") rather than the spec's live "1 {unit} = {numerator ÷ denominator} {base unit}" sentence: `CrudForm` has no live preview, and the saved row shows the sentence at once. Building a preview into the shared form for one hint was not worth it (review L3).
- **Review fixes (code review on #50, verdict approve):**
  - a PATCH changing nothing is `VALIDATION_FAILED` under `changes`;
  - the (de)activate confirmation keeps the action it opened with after a stale-version refresh;
  - the empty list names the tenant and tells the admin how to start;
  - `MATERIAL_IDS_EXHAUSTED` is translated;
  - `BACKWARD_COMPATIBILITY.md` says tenant pages need a session, not the admin;
  - the audit isolation check finds the Action column by its header.
- **A conversion's inverse is shown in its shortest form** (`"0.083333"`, `"3"`), like factors; stored quantities use the fixed six decimals.
