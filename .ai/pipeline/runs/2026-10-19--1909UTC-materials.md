## Goal

In each tenant the admin creates and edits materials: an eight-digit ID assigned in sequence per tenant, a type, a description, a base unit, an active flag, and exact conversions from other units. Every signed-in user views them, in the UI and through the API. An entered quantity converts into the base unit once, half-up to six decimals, without binary floats. Test is seeded with demo materials.

## Risks

- **The spec is not on `main` while this is built.** It comes from spec PR #49 and is kept as an untracked file in the worktree; it moves to `implemented/` once #49 merges.
- **Three ⚠ assumptions (Q5, Q9, Q13).** The PR stays a draft until the owner confirms them on #49.
- **SQLite stale snapshots.** The new retry in `tenantServerAction` must not retry real lock timeouts. A two-ORM race test proves both paths.

## Deviations from the spec

- **The seed lives in `core/src/demo-data.ts`**, not `database.ts`: it builds a container, and `container.ts` already imports `database.ts`, so putting it there would make an import cycle.
- **`VERSION_CONFLICT` and `versionConflict()` moved to `http/errors.ts`** for the second versioned service; `versionSchema` moved from `validators/users/` to `validators/version.schema.ts`. Both were planned in #21's notes for this story.
- **The migration's `down()` drops `material_conversion` before `material`** (hand-reordered before the first push): the generated order fails SQLite's foreign-key check on a table with rows. A test rolls it back with rows present.
- **A conversion's inverse is shown in its shortest form** (`"0.083333"`, `"3"`), like factors; stored quantities use the fixed six decimals.
