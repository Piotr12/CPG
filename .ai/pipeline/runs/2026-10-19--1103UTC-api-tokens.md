## Goal

Any signed-in account creates named API tokens at `/admin/tokens` and sees each secret once. It lists and revokes them there or through the API. Every `/api` route accepts `Authorization: Bearer <token>` with the owner's rights. No API route mints a token. A reset, a deactivation or an admin-password change deletes the affected tokens.

## Notes

- **The worktree had no `node_modules`.** Node resolved `@cpg/*` to the main checkout's packages, so tests would have exercised the wrong code. Ran `npm ci` in the worktree first.
- **Missing admin-password stamp at startup:** the spec said "store the hash, delete nothing", reasoning that no admin token can exist yet. The code deletes any admin token it finds when the stamp is missing: the same outcome on a real first start, and fail-closed if the row was ever lost.
- **Compare-and-set on the stamp uses `count`, not `findOne`.** The identity map already held the stamp read before the transaction, so `findOne` returned the stale value and the deploy-overlap test caught it.
- **`requireApiUser` returns `ApiCaller` (`ApiActor | SessionUser`).** `assertSignedIn`/`assertAdmin` are generic over `Actor`.
- **A duplicate name is a form-level alert, not a field error.** `ConflictError` carries no field, the same as for usernames on the users screen. The mockup's under-the-field placement is illustrative only.
- **Integration files share one database.** The new file runs before `users.test.ts`, and its users and the startup admin-password stamp broke `users.test.ts` and `smoke.test.ts`. Both now assert only on their own records (`aliceRow`), and the smoke test expects the stamp (`1 settings`). Recorded as a lesson.
- **Build log.** `npm run build` now logs "Route handler failed … used request.headers" for `/api/tokens` and `/api/users` as well as `/api/tenants`. It is the prerender bail-out already filed as #38, not a failure: the build succeeds and the routes are dynamic (`ƒ`).
- **Docs.** The routes, the authentication contract and the announced `Idempotency-Key` are in `BACKWARD_COMPATIBILITY.md`; bearer authentication and the adoption status are in the engineering standards.
