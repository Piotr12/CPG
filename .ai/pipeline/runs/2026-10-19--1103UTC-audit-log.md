## Goal

Every account-level change is recorded in an append-only Global audit, and each tenant has its own append-only audit. Entries hold before/after values, time, account, session and channel, and never a password, hash or secret. Every signed-in account can read both audits on `/admin/audit` and `/admin/{tenant}/audit` and through `GET` API routes, and nobody can edit them.

## Scope

- `packages/db`:
  - `entities/audit/{audit-event,global-audit-event.entity,tenant-audit-event.entity}.ts`;
  - `entities/index.ts`;

## Non-goals

- Audit producers for tokens (#17), read-only flags (#25) and the Test reset (slice 2).
- Filters, search and export in the viewer.
- Bearer-token API authentication.

## Risks

- The trigger SQL is hand-written into a generated migration, so a migration test must prove it.
- `actor` becomes a required argument on two services, so every call site and test changes.
- #17 and #25 are open and may touch `UserService` in parallel.

## Notes

- The append-only triggers are declared on the entities (MikroORM 7 `triggers`) instead of hand-written into the migration as the spec proposed. `db:migration:create` generated the same SQL, the snapshot tracks them, and a second `create` reports no drift, so a later migration can't silently lose them.
- `onCreate` runs inside `em.create`, so a new user's id is known when its audit entry is created in the same flush.
- The header link reads "Global audit" and the tenant link "Audit — {tenant}" instead of the spec's "Audit" for both: on a tenant page both links show, and two links named "Audit" leading to different audits would be ambiguous.
- `core/src/http/parse-input.ts` (`parseInput`, `validationError`) was added so routes and pages parse query strings the way `serverAction` parses input, without a second inline copy; `serverAction` now uses `validationError`.
- A malformed `?before=`/`?limit=`, or a cursor from another audit, renders the not-found page on the screens (400/404 through the API).
- `tests/integration/users.test.ts` now ignores accounts other files create (integration files share one app; users are never deleted).
- 999cdc0 fixed a type error in the Phase 1 entity test that my Phase 1 typecheck output had hidden (`tail` cut it off).
- `recordGlobalAudit`/`recordTenantAudit` stay internal to `core` (only `uiActor` and `Actor` are exported): every producer is a core service.
