# Monorepo architecture: packages, SQLite/MikroORM, Awilix, shadcn

**Date:** 2026-10-17
**Agent:** Claude Code (claude-opus-5-5) via cezar

**Status:** done

## Goal

Turn the single Next.js app into an npm-workspaces monorepo (`packages/app`, `core`, `db`, `ui`), wire SQLite via MikroORM (migrations), Awilix DI, Tailwind for frontend pages and shadcn/ui for backend (admin) pages. Store the DB and all other files in `/externaldata` inside the container, bind-mounted from `/externaldata/cpg.baby` on the VM. Record the stack in `AGENTS.md`, rewrite `README.md` with architecture notes (shorter prose, some humour kept). Push to `main`.

## Plan

1. `git mv` the Next app into `packages/app`; root `package.json` becomes the workspace root.
2. `packages/core`: env config (`DATA_DIR`, DB path) + Awilix container factory.
3. `packages/db`: MikroORM (`@mikro-orm/sqlite`, better-sqlite3) config, entities via `defineEntity`, explicit `migrationsList` (bundler-safe), migration CLI script run with `tsx`, Awilix registrations.
4. `packages/ui`: shadcn/ui components (`cn`, Button, Card), theme CSS.
5. `packages/app`: container singleton, migrations on boot (`instrumentation.ts`), `/up` pings the DB, Tailwind landing page, shadcn `/admin` page.
6. Docker/Kamal: standalone output traced from repo root, `volumes: /externaldata/cpg.baby:/externaldata`, `DATA_DIR=/externaldata`.
7. Docs: `AGENTS.md`, `README.md`, `packages/app/AGENTS.md` (Next's managed block lives next to the app now).
8. Verify: `npm run lint`, `npm run typecheck`, `npm run build`, run dev + prod standalone, `docker build` + run with a mounted volume.

## Log

- VM check (read-only ssh): `/externaldata/cpg.baby` exists, mode 777 — the container user (uid 1001) can write; no host prep hook needed.
- MikroORM is at v7 (`@mikro-orm/sqlite` uses better-sqlite3 + Kysely). Awilix 13.
- Entities use `defineEntity` with explicit names, and migrations are listed explicitly (`migrationsList`, index regenerated by the CLI script), so nothing depends on folder globbing or class names surviving the bundler/minifier. A `Setting` key/value entity exists because MikroORM refuses to start with zero entities.
- Turbopack warned that `core/config.ts` made it trace the whole project (dynamic `fs` paths). Fixed with `/* turbopackIgnore: true */`.
- **Re-plan:** at first `instrumentation.ts` built the shared container. `/admin` then crashed because route handlers, pages and instrumentation each get their own copy of `@cpg/db`, and MikroORM matches entities by object identity. Now instrumentation only runs `migrate()` with a short-lived ORM, and `getContainer()` keys its singleton by the `entities` array. Recorded as a lesson.
- Docker `npm ci` failed: npm runs `node-gyp rebuild` for better-sqlite3 (it has a `binding.gyp`). The package ships prebuilt binaries for musl, so the fix is `npm ci --ignore-scripts`. File tracing copies the x64 prebuilds into standalone.
- The hand-written shadcn `new-york` components were outdated. A reference `shadcn init --monorepo` scaffold in /tmp showed the current setup: `radix-nova` style, `cn` npm package, `shadcn/tailwind.css`. Aligned `packages/ui` with it and regenerated button/card/badge with the CLI.
- `next dev` writes its managed AGENTS block next to the app, so it now lives in `packages/app/AGENTS.md` (+ `CLAUDE.md` importing it). The root AGENTS.md has a new "Stack and architecture" section instead.
- Removed the create-next-app SVGs and template page; added a Tailwind landing page, a shadcn `/admin` page with DB status, and `robots.txt` (also keeps `public/` non-empty for the Docker COPY).
