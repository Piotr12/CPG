## Database, MikroORM and SQLite

- **2026-10-19 — MikroORM filters and the flush don't see every write** — the `tenant` filter covers `find*`, `count`, populate, `nativeUpdate` and `nativeDelete`, and `TenantGuard` sees only flushes. These bypass both:
  - `insert`/`upsert`/`clone`;
  - the QueryBuilder (root, `from()`, `clone()`, joins);
  - `getDriver()` and `addFilter()`;
  - `nativeUpdate` data with a relation key or raw column name.

  `TenantEntityManager` refuses them at runtime, and ESLint bans the QueryBuilder, the driver, `addFilter` and raw SQL in `core`/`app`. The same lint rule fires on any property named `filters`, a React prop included: name it `selected`, never disable the rule. After a MikroORM upgrade, re-read the `EntityManager` write methods and run `packages/db/src/tenants/tenant-isolation.test.ts`.
- **2026-10-23 — The identity map hides and discards changes** — three traps:
  - a `findOne` of an entity already loaded returns the cached value, so compare-and-set with `count(Entity, { key, value })` (`ApiTokenService.create`);
  - a `refresh: true` read re-hydrates the managed instance and drops its unflushed changes, so flush your own edits before calling a helper that refreshes (#147, `completeFinishedShipments`);
  - don't pass `disableIdentityMap` to a read inside `em.transactional()`: it reads from a fork and once missed rows the transaction had just deleted. Read through the transaction's own `em`.
- **2026-10-20 — Open transactions on the request `em`, never with `em.transactional()` on it** — forks have `useContext = false`, so a fork's transaction is invisible to services holding the request `em`. Their own transaction then waits forever for the single connection, and repeated `trx1` savepoints roll back the wrong one. Use `inRequestTransaction` / `inRequestSavepoint` (`core/src/http/request-transaction.ts`), which use `em.begin()` on the request `em`.
- **2026-10-24 — better-sqlite3 is synchronous: a long write freezes the whole server unless it yields** — a locked connection busy-waits in C, and a long loop of service calls never yields to the event loop: the awaits between synchronous statements resolve as microtasks, so sockets are never read. During the realistic Test reset (#126) every request waited, `/up` and static files included (on a fresh connection; a reused one can fail instead, see the next lesson). Two rules from #185:
  - a long write loop `await`s a `setImmediate` after each unit of work (`seedTestTenantDataset`), so requests are read; its own bundle's requests then queue behind the transaction on Kysely's connection mutex and complete after the commit;
  - the other Next.js bundles have their own ORM and connection (lesson of 2026-10-17: route handlers, pages and instrumentation are three copies in the standalone build), so their transactions are *not* on that mutex: one begun mid-write reaches SQLite and gets "database is locked" at once (a WAL read-to-write upgrade skips the busy handler). A transaction that yields must hold the write gate (`holdWriteGate` in `@cpg/db`), which `WriteGate` makes every other connection's root transaction await until the commit or rollback. The gate sees transactions only: a native write outside one (`nativeUpdate`, `nativeDelete`) goes straight to SQLite, busy-waits in C for better-sqlite3's 5 s timeout and stalls the whole process, so wrap it in `em.transactional` (`recordUse`, `deleteSession`). Prove a cross-bundle claim with two ORMs on one file, never with one;
  - anything that must answer *during* such a write must not take the ORM's connection: Kysely's `RuntimeDriver` holds its mutex from `begin` to `commit`, so the health check pings the native better-sqlite3 handle instead (`pingDatabase` in `@cpg/db`).

  Never hold the write lock across real async work (argon2, I/O): read first, write last (`IdempotencyService.run`). When a change adds a bulk write, time a few requests issued *during* it, `/up` among them (`.ai/pipeline/runs/2026-10-21--1237UTC-test-tenant-dataset/timings.md`, `test-reset-realistic.test.ts`).
- **2026-10-24 — A blocked event loop closes pooled connections unread** — while the realistic reset blocks the server, a request sent on a kept-alive connection whose idle timer (Node's `keepAliveTimeout`, 5 s) has expired meanwhile is not read: when the loop unblocks, timers run before I/O, the server closes the socket, and the client gets `ECONNRESET`. curl and fresh connections hide it (the 2026-10-21 timings saw only successes). kamal-proxy pools connections to the app and never closes idle ones, and Go retries only a request without a body (`isReplayable`: GET/HEAD/OPTIONS/TRACE, or bodiless with `Idempotency-Key`), so every queued write with a body would answer 502, API writes with an `Idempotency-Key` included. The image sets `KEEP_ALIVE_TIMEOUT` to an hour (#185). Probe a blocking operation with a client that reuses connections, Node's `fetch` after an earlier request.
- **2026-10-22 — Bulk writes: chunk, clear the identity map, and count ORM calls** — every flush walks the whole identity map. A 2,000-row import went from 17.9 s to 0.4 s once it cleared the map after each row (`runRow`), and a 2,000-line stock posting from 23.5 s to 1.2 s once it flushed in chunks of 25 with `em.clear()` (`StockImportService.commit`).
  - Paged recalculations must flush and clear finished batches too, keeping only primitive cursors.
  - Measure a bulk write at its row cap before shipping.
  - The generated-dataset seed is bound by MikroORM's per-call cost (~6.4 of 8.9 s), not SQLite, so fewer ORM calls per document is the lever: a seed path returns only the IDs the seeder needs instead of reading the document back (`seedDemo`), a posting loads its materials, locations and balances in one query each (`postStockMovements`), and `@cpg/db` caches prepared statements (`cacheStatements`). Together they took the realistic reset from 10.7 s to 7.6 s in the unit test (#185); don't chase it further unless a budget demands it.
- **2026-10-19 — Two racing creates on SQLite fail as a stale snapshot, not a unique violation** — the loser gets `SQLITE_BUSY_SNAPSHOT` at its first write. Retry the whole transaction once (`retryingStaleSnapshot`); the unique index is only a backstop. Prove it with a two-ORM test.
- **2026-10-23 — Review every generated SQLite migration that rebuilds a table** — `db:migration:create` rebuilt referenced tables and copied `NULL` into new `NOT NULL` columns despite defaults (#90, #147).
  - Prefer additive `ALTER TABLE` columns.
  - To widen a `CHECK` enum, hand-write it: add a checked column, copy into it, drop the old one, rename the new one.
  - Test the upgrade on populated data, and assert `orm.schema.getUpdateSchemaSQL()` doesn't mention the table (`shipment-edit-cancel-migration.test.ts`).
  - Don't extend a protected enum (`TransferPosting.kind`): it rebuilds the table and changes an API value clients switch on.
- **2026-10-21 — Releases overlap: migrations and backfills must tolerate the previous image** — independent migrations can land in a different order than production applied them, and an old container keeps writing during a deploy. Test pending-migration adoption on the current base schema, and derive states from authoritative quantities rather than a one-time backfill. Test an old-style write after the migration.
- **2026-10-25 — SQLite's text functions are ASCII-only: change the connection's function, not the schema** — `LIKE`, `lower()`, `upper()` and `NOCASE` fold ASCII letters only, so `łożysko` missed `Łożysko` (#223). `initOrm` replaces `like()` with `registerUnicodeLike` (`packages/db/src/unicode-like.ts`); do the same for any other text function rather than adding shadow columns. A better-sqlite3 function must return a number, string, bigint, Buffer or `null`, never a boolean. SQLite resolves functions by name *and* argument count, so register each arity: `X LIKE Y ESCAPE Z` is the three-argument `like`.
- **2026-10-19 — MikroORM 7 entities can declare triggers** — `defineEntity({ triggers: [...] })` makes `db:migration:create` emit and snapshot them. Prefer it to hand-written trigger SQL (the audit's append-only triggers).
- **2026-10-19 — `p.….nullable()` infers `T | null | undefined`** — an entity still in the identity map from this request's `em.create` has unset optional fields as `undefined`. Map with `?? null` when a view promises `null`, and test by reading back through the same `em`.
- **2026-10-21 — A version bumped through a timestamp needs a monotonic timestamp** — touching a parent's `updatedAt = new Date()` within the stored millisecond changes nothing, so the version stays put (#142). Use `new Date(Math.max(Date.now(), stored + 1))`, as `resolve()` does, and pin the clock in a test.
- **2026-10-21 — Sort and page by business ID, never by the UUID a reference holds** — the stock report tallied by `material.id` and came out in random order. Map references to `code` first. Test ordering with more rows than a page, fed in an order where UUID and code differ: SQLite returns unordered finds in insertion order, which already looks sorted.
- **2026-10-19 — Same-millisecond audit entries sort by their random id** — two entries written back to back can come out in either order. Separate them in time, or assert without order.
- **2026-10-23 — EXPLAIN the query MikroORM really sends** — capture it with `initOrm(options, { onQuery })`, run the real `findOne` on a `selectTenant` fork, and `explain query plan` the captured SQL. A hand-written copy misses the joins the tenant filter adds (#162, `location-guard-index-migration.test.ts`).
- **2026-10-25 — A mixed-direction sort needs its own index, declared as an `expression`** — an index on `(tenant, column, code)` read backwards gives `column DESC, code DESC`, so a list sorted `column DESC, code ASC` (ties by ascending ID, #217 D3) still sorts the whole tenant. It needs a second index, `(tenant, column DESC, code)`. MikroORM 7 reads SQLite index columns back without their direction, so one declared with `columns: [{ sort: "desc" }]` never matches the database and `getUpdateSchemaSQL()` keeps recreating it. Declare it as an `expression` (`listSortIndexes` in `db/src/entities/lists/`, #220).
- **2026-10-17 — One ORM per Next.js bundle, keyed by entity identity** — route handlers, pages and instrumentation get separate copies of `@cpg/db`, and MikroORM matches entities by object identity. Never cache the container on `globalThis` under a string key; `getContainer()` keys it by the `entities` array. [details](lessons/2026-10-17--0920UTC-mikroorm-entity-identity-next-bundles.md)

## Services, domain rules and errors

- **2026-10-21 — Locks follow immutable posting history, not net progress** — a full reversal returns `received`/`fulfilled` to zero but doesn't make a document unprocessed. Derive identity and edit locks from immutable posting references (`postedReferences`, `services/stock/posted-references.ts`), keep explicitly closed lines closed, and let headers follow retained line states (#91, #138).
  - Replacing a line's material must archive the old line first, or the old FK, and its type/base-unit lock, is lost.
  - A transfer write-off has no stock movement, so transfer reversals link through their own append-only `TransferReversal`.
- **2026-10-24 — Paging a list: bound it from the first release, and move every decision off it** — paginate growing document collections in the service and API, fetch only the page's lines, and bound guards and previews (current recipes only, batched lookups, an index covering the filter plus cursor).
  - When you page an existing list, grep the screens for decisions read from it (`.some`, `.length`, `.find`) and move them into server-computed fields (#138).
  - Grep the tests that count it whole too, both unit and integration (#140).
  - A before/after snapshot that proves "nothing changed" must walk every page, or it proves it for the first 100 records only: read a paged list through `allPages` in `tests/integration/api.ts`, and make the test itself put the list past one page so a first-page read fails (#201).
- **2026-10-23 — Refusals carry structured `params`; messages stay fixed text** — screens translate by code and exact message, so put record IDs and quantities in `params`, e.g. `new ValidationError(fieldErrors, { material })` or `ConflictError(…, code, { order })`. Never interpolate them into the message (#153).
  - Keep `params` through every adapter: HTTP, server actions, import reports.
  - Give every new code EN/PL text, and keep an unparameterised fallback.
  - `serverAction` passes a service's `ValidationError` field errors through to the form.
- **2026-10-20 — A Zod object drops unknown keys: refuse a locked field with `z.never()`** — a PO line `PATCH` with `quantity` answered 200 and ignored it. Declare every refused field `z.never({ error: … }).optional()` and test the 400 per field. `validationError` keys list errors by their full dotted path (`components.2.unit`), not `z.flattenError`'s first segment.
- **2026-10-20 — Bound an uploaded workbook by the cells it spans, not only its bytes** — `read-excel-file` pads every row to the last column and adds a row for every gap. A 1.4 KB file with one cell at `XFD10000` ran the server out of memory. `readWorkbook` refuses more than 200,000 spanned cells first (`cellsSpanned` in `components/imports/workbook-file.ts`). Such a pre-check must parse addresses the way the library does, with a test for each disguise.
- **2026-10-20 — Read tenant state inside the write transaction** — a tenant scope captures metadata before the transaction. A preview hashed against the captured generation could commit against a reset's reseeded IDs. Read `TenantService.currentState` inside the apply transaction, and test across a real reset.
- **2026-10-20 — Keep advisory reads out of tenant write actions** — every exported tenant server action is a gated write, so a read-only tenant can't preview through one. Serve previews from an authenticated GET through `apiCall`, keeping error params and field errors.
- **2026-10-21 — Check a service method's caller contract before reusing it on a wider page** — `UserService.list()` expects `assertAdmin` first, and the audit pages are open to every account (#96). Add a narrow read (`usernames()`) documented as safe for the wider audience.
- **2026-10-20 — Never take the rest of an Awilix PROXY cradle** — `({ em, ...services })` enumerates and resolves every registration, the service itself included: "Cyclic dependencies detected". Destructure each dependency by name.
- **2026-10-21 — Vary a service's configuration through the container, not `vi.mock`** — the dataset configurations are the container value `testDatasets`; a test registers `asValue(...)`. Do the same for any constant a service reads and a test must change.
- **2026-10-23 — Resolve conflicting sources with the owner before fixing a contract** — the #80 backlog and INV-006 described signed stock changes, while decision §03 said target balances. Compare issue, decision register and conceptual model, then record the owner's resolution as a named decision (D07), keeping the conflicting source as an erratum.
- **2026-10-23 — List what an audit writes at the point of the write** — snapshot keys come from helpers, spreads and computed names, which a source scan misses. The recorder refuses fields outside `AUDIT_FIELDS`, and the label test checks that list (#145).
- **2026-10-25 — Keep a unit out of entry at the choke point, and at every picker source** — every entered quantity goes through `convertToBaseQuantity`, so a unit that must never be entered (`SU`, #239) is refused there, which covers all fifteen entry paths and the imports at once. The pickers are separate sources: `MaterialService.listUnits`, the completion preview's `units`, the Stock page's list and the demo catalogue's `unitsOf`, plus `unitSelect` for base units. The document services report the refusal as `VALIDATION_FAILED` on the line's `unit` field; only stock corrections and the stock import keep the raw `UNIT_NOT_CONVERTIBLE` code, so a test per entry family must assert the shape that family returns.

## UI and React

- **2026-10-24 — Design tokens: `--input` is a boundary, never a fill** — since design system v1 `--input` is the opaque 3:1 control border, so shadcn's `dark:bg-input/30`, `disabled:bg-input/50` and `dark:hover:bg-input/50` paint grey fields and buttons; use `bg-muted` for a disabled fill and `bg-background` with `border-border` for an outline button. Likewise an invalid control's border is `border-danger` (the `danger-edge` tint measured 1.74:1 on white); `tokens.test.ts` pins both floors.
- **2026-10-24 — `Button` publishes its variant as `data-variant`, and tests select by it** — integration tests find a confirm button with `[role=alertdialog] button[data-variant=destructive-solid]`, so renaming or swapping a variant (W2 moved `ConfirmDialog` to `destructive-solid`) moves a dozen selectors: grep `tests/integration` and the unit tests before changing one.
- **2026-10-24 — Tailwind 4 orders `aria-*` variants after `focus-visible`** — an `aria-invalid:ring-…` colour overrides the focus ring on a focused invalid field. Give invalid controls a border only (`aria-invalid:border-danger`) and leave the ring to `focus-visible`, or add `aria-invalid:focus-visible:ring-ring` when an invalid ring is unavoidable.
- **2026-10-25 — A new status needs a sweep of status-specific copy, and a banned term a guard** — When an enum gains a value, check EN/PL messages for the guarding error codes and old status names; use neutral or parameterised text and test it through the screen. After #147 added shipment cancellation, the goods-issue dialog still called a cancelled shipment completed (#188). When the glossary retires a word (design system v1: BOM, not recipe), sweep both dictionaries, `help/topics.ts` and the import template's prose and examples in `workbook-layout.ts`, and add the word to the guards in `messages.test.ts`, `help/topics.test.ts` and `workbook-layout.test.ts`, which fail on any value that still uses it (#206). The server's English texts follow too: add the word to `tests/api-messages-glossary.test.ts`, which scans every string and JSX text in `core` and in the app's routes, pages, server actions, auth and routing. List each reworded API `message` in BACKWARD_COMPATIBILITY.md, and keep exact-text lookups on the exported constants so they follow the change (#214).

- **2026-10-19 — A client component must not import a module that imports `@cpg/core`** — the browser bundle pulls in the ORM, and only `npm run build` fails. Keep client helpers dependency-free (`components/layout/current-path.ts`) or import `@cpg/core/validators/*`.
- **2026-10-24 — A label passed to a client component must be plain data** — function-valued labels pass unit tests but the server refuses the page. Use `{ one, other }` forms (`counted` in `components/imports/report-text.ts`; Polish needs a `few` form for 2–4), and test that labels hold no function. The same trap hides in a whole dictionary section (`messages.nav` holds functions): pick the plain strings a client component needs instead of passing the section (the tenant not-found page's `BackLink`).
- **2026-10-19 — React 19: updates after `await` leave the transition** — wrap post-await `setState` in another `startTransition` (`ui/src/backend/forms/crud-form.tsx`), or an error can show while `isPending` is still true.
- **2026-10-19 — Name a function `useX` only if it is a React hook** — `react-hooks/rules-of-hooks` treats every `useX()` call as a hook (hence `selectTenant`).
- **2026-10-21 — Dialogs and refresh: bind to what was opened, keep what explains a refusal** — three rules:
  - capture the record and its version when a dialog opens, and keep them until it closes;
  - refresh after a refusal only if the controls showing the error survive it (`VERSION_CONFLICT` does, `TENANT_READ_ONLY` doesn't);
  - defer the refresh while a dialog's row may disappear.

  Keep a create draft outside a disposable preview, so Back restores it.
- **2026-10-20 — Tall dialogs and dense tables need real-browser checks** — two layout traps:
  - shadcn's `DialogContent` doesn't scroll, so give tall forms `TALL_DIALOG` (`components/forms/form-labels.ts`);
  - `TableCell` is `whitespace-nowrap`, so wrap unbounded columns (`whitespace-normal`, `wrap-anywhere`), hide secondary ones below `sm`, stack row actions (`flex flex-col items-start`) and keep IDs `whitespace-nowrap`.

  Assert overflow (`scrollWidth` vs `clientWidth`) and that row actions stay in view at 1280 px and 390 px.
- **2026-10-20 — Sidebar changes** — every new entry needs:
  - an icon in `sidebar-nav.tsx`'s exhaustive registry, or the sidebar fails at runtime;
  - to fit 1280×800 without scrolling, so add tenant entries flat rather than as a new group;
  - in the icon rail, text hidden with `group-data-[collapsible=icon]:hidden`.

  The mobile `Sheet` doesn't return focus to its opener; `SidebarNav` does it. In tests, scroll a sidebar target to the centre of its container before clicking: the fixed shared menu can cover it. Run `navigation.test.ts` after any nav change.
- **2026-10-19 — The root layout's client state survives navigation** — a popover or sheet left open covers the next page. Close overlays on `usePathname()` change with controlled `open` state (`nav-menu.tsx`).
- **2026-10-23 — Filter forms: render refusals in the form and keep values they don't list** — a refused filter is not a 404: keep `notFound()` for page positions and cursors (#96).
  - An error present at page load must be rendered through `ErrorSummary`, because screen readers skip a server-rendered `role="alert"`.
  - A `<select>` whose `defaultValue` matches no option silently submits its first option, so add the URL's value as its own option (#152).
- **2026-10-21 — Pages show a visible loading state, from the first streamed frame** — new or touched data pages use `LoadingMessage` as their Suspense fallback (CODE_REVIEW.md), not the blank placeholders older pages copied. QA captures the cold-load frame.
- **2026-10-23 — Adapt shared help copy to each topic** — #90 pasted "Headers stay Open while any line is Open…" onto production orders, requisitions and transfers, which have no lines. #91 put the issue-reversal paragraph on the purchase-order page. Fix both languages.
- **2026-10-25 — A popup inside a Radix dialog: claim Escape before the dialog, and measure the room it has** — Radix's `DismissableLayer` listens for Escape on `document` in the **capture** phase, so an input's own `onKeyDown` (even with `stopPropagation`) runs too late and Escape closes the whole dialog (design proposal B's prototype). While its list is open, `Autocomplete` adds a `window` capture listener that `preventDefault()`s Escape, which Radix honours; `CrudForm` skips keys already `defaultPrevented`. A list absolutely positioned inside `TALL_DIALOG` (`overflow-y-auto`) is clipped at the dialog's edge, so measure the nearest scrolling ancestor and open upward when the room below is short (`placeList`, #217). Test both inside a real `Dialog`.
- **2026-10-25 — Read the server's markup only while hydrating** — `FilterAutocomplete` read `document.getElementById(id)` in a `useState` initializer, to keep a choice made in the server's select before hydration. It ran again on every remount (`key` changes on Clear filter or Back), when the element with that id is still the old combobox, so the next filter submitted a display label (#222 review). Gate such reads on the hydration flag (`useSyncExternalStore`'s server snapshot), and test a re-render with a new `key`.
- **2026-10-19 — shadcn quirks** — `import { cn } from "cn"` in generated components is correct, and this repo's style is `radix-nova` (not `new-york`). The generated `use-mobile` hook fails lint: re-apply the `useSyncExternalStore` version after a `shadcn add` regenerates it. jsdom drops the space in an `sr-only` span's accessible name, so use an explicit `aria-label`.

## Unit tests

- **2026-10-21 — Cite a scenario only where a test asserts it** — a test title carries a catalogue ID only if its assertions cover the Then; wiring tests with mocked services describe the wiring (#70, #140). Before promoting a catalogue row to `Passed (automated)`, match every clause of its Evidence line to an `expect`.
- **2026-10-21 — A spy on an `em` doesn't see a service's `em.transactional()`** — the callback gets a fork. Route it back with `vi.spyOn(em, "transactional").mockImplementation(async (cb) => cb(em))` (`spyableEm`). To prove a real rollback after a partial flush, make a call inside the transaction throw instead (`transfer.service.test.ts`).
- **2026-10-23 — A new migration moves every migration count** — update:
  - the lists in `orm.test.ts` and `core/src/database.test.ts`;
  - the counts in `system-status.service.test.ts` and `smoke.test.ts`;
  - one more `down()` in every rollback-by-count test.

  `migrator.down({ to })` keeps `to` applied, so call `down()` once per migration. Never run migrator calls under `Promise.all`. The "adopts …" tests apply a filtered subset, so filter a migration out with the table it indexes.
- **2026-10-17 — React DOM can't render async server components** — await the page function and its async children before `render()` (`resolveServerComponents` in `app/src/app/admin/page.test.tsx`).
- **2026-10-19 — A hook must not return a function by accident** — `beforeEach(() => mock.mockResolvedValue(x))` returns the mock, which Vitest runs as teardown. Give hooks a block body.
- **2026-10-21 — jsdom gaps are stubbed once** — `tests/setup/dom.ts` stubs `ResizeObserver` (Radix checkbox); don't stub per test. Inside a cell, `querySelectorAll("tbody tr")` also matches through ancestors: prefix `:scope`.
- **2026-10-22 — Vitest drops a passing test's console output** — write a figure CI should record with `process.stdout.write(…\n)`.
- **2026-10-23 — Prove a sequence restart from a generation that went further, in every kind** — after a reset to the same dataset, `00000001…N` looks the same whether the sequence restarted or the rows were never touched. Reset realistic → tiny, assert the old generation had more of every kind (add rows where both datasets match), and derive the sequenced tables from the metadata (tenant-owned with a `code`) so a new kind fails until covered (#189, TEN-029).
- **2026-10-23 — Interleave a write with a reset from the caller's transaction, not a spy** — read the generation, commit a write on a second connection through `IdempotencyService.run` (where the API checks generation and read-only), then call `reset()`, all under `retryingStaleSnapshot(inRequestTransaction(…))`, and count the attempts to prove the retry happened (#189, TEN-026).
- **2026-10-21 — Check a generated dataset's property on every day before relying on it** — the #126 fixture's "more than one page" held only on some seed dates. Run the generator over the whole window in a scratch test, pick a fixture that always holds, and assert the property, never top it up.
- **2026-10-17 — `tmpdir()` can be inside the repo** — cezar points `TMPDIR` at `.ai/cezar/tmp/…`. Use the filesystem root when a test needs "no workspace above me".
- **2026-10-17 — Root-level config files are `.mts`** — the root `package.json` has no `"type"` (`vitest.config.mts`, `vitest.integration.config.mts`).

## Integration tests and agent-browser

- **2026-10-24 — A test that compares two Test generations owns both resets, within one UTC day** — the server seeds the dataset of `new Date()`'s day, so the generation an earlier test or the server's start left may be another day's: today's documents change daily, and every ID shifts at a month boundary. Reset first, run the scenario under `withinOneDay` (`test-reset-api.test.ts`, which re-runs it once when the day changed), and check the property you pick on over the whole window (E2E-020, #200).
- **2026-10-24 — A `StatusBadge`'s `innerText` breaks the line before its label** — the icon is a flex item, so a row's `innerText` reads `"\nActive"`; match row text with `\s*` or read the label span. A second integration pass on a server already used by a first fails on its fixed usernames and records: copy the standalone build and give it a fresh `DATA_DIR` for every pass (P3 of the design system run).
- **2026-10-22 — Integration files share one app, one admin and one database** — files run one at a time (`fileParallelism: false`). A file:
  - restores the admin's preferences in `afterAll`;
  - revokes only the tokens it created;
  - leaves its own uniquely named accounts active;
  - asserts only on its own records (`ownRows`; filter audit rows by the record's `${id} — <name>` label, since every master numbers from 00000001);

## Process and agent pipeline (om-* skills)

- **2026-10-24 — A closing keyword anywhere in a PR body closes the issue** — GitHub parses `closes #N` / `fixes #N` / `resolves #N` in any sentence of the body, so the spec PR #204, which opened with `Refs #203` and later said "its implementation PR closes #203", closed the issue on merge. A PR that must leave an issue open (a spec PR, a partial fix) never puts a closing keyword next to that number, not even about a future PR: write "the implementation PR will close it" without the number, and grep the body for `clos|fix|resolv` before opening it.
- **2026-10-24 — A lead-and-workers run: briefs in the run folder, viewport screenshots, one hunk per worker** — three rules from the design system run (`.ai/pipeline/runs/2026-10-24--0925UTC-design-system-v1/`):
  - a cezar dispatch objective is capped at 4,000 characters, so commit each worker's full brief under the run folder and make the objective point at it;
  - evidence screenshots are viewport captures (a full-page Help capture was 37,000 px tall and 3.4 MB), with the measurements in a `metrics.json`;
  - parallel workers may share a file only when their hunks are disjoint (a dictionary's concept sections) and a worker that needs one assertion outside its scope asks the lead, who authorises that hunk and tells the file's owner to stay off it.
- **2026-10-23 — Close the paperwork in the PR that does the work** — two rules:
  - File every follow-up a PR, spec or run log names before merging, and cite its number. Prose follow-ups were lost (#109's location guard, #95's reversal check).
