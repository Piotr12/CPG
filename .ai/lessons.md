# Lessons learned

Long-term memory for AI agents working on this project. **Read this before starting any task.**

Add an entry after fixing a bug, hitting a non-obvious pitfall, or discovering anything worth remembering. Update or delete entries that turn out to be wrong. One bullet per lesson, grouped by topic:

```markdown
- **YYYY-MM-DD — <short title>** — <what happened / what to do instead>. [details](lessons/YYYY-MM-DD--HHMMUTC-slug.md)
```

The `[details]` link is optional — add a file in [`lessons/`](lessons/) only when the lesson needs a longer write-up.

## General

- **2026-10-21 — A long loop of service calls on better-sqlite3 freezes the whole server** — every statement runs synchronously and every `await` between them resolves as a microtask, so the generated-dataset reset (#126, about 3,700 documents in one transaction, ~10 s) never yields to the event loop. Every request waits until it commits: Prod writes, reads, `/up`, even static files. The spec had expected only other bundles' writes to fail after the 5 s busy timeout. When a change adds a bulk write, time a few requests issued *during* it, not only its own duration (run folder `2026-10-21--1237UTC-test-tenant-dataset/timings.md`).
- **2026-10-21 — Check a generated dataset's property on every day before a test relies on it** — the #126 spec chose the ledger of 00000007 at 00000001 to show "more than one page", but that pair has 97–100 movements depending on the seed date. The first integration test hid it by posting corrections until a second page appeared. Run the generator over the whole window in a scratch test, pick a fixture that holds on every day (each finished product has 131+), and assert the property, never top it up.
- **2026-10-21 — Let tests vary a service's configuration through the container, not `vi.mock`** — the #126 reset tests mocked the dataset-config module to shorten the history, which is an internal module, not a boundary (AGENTS.md). The configuration is now the container value `testTenantConfig`; a test registers `asValue(REDUCED_TEST_TENANT_CONFIG)` on its container. Do the same for any constant a service reads and a test needs to change.
- **2026-10-21 — File every follow-up a PR or spec names before it merges** — The slice 2 epic closures found two gaps that were written down and never filed. The location-deactivation guard for Open POs was flagged in PR #109, in the spec notes and in the run log. The variance report's real-reversal check was handed from #95 to #92 in a comment. Neither landed. A "follow-up" that exists only in prose is lost: file it (or name the issue that owns it) before merging, and cite the number in the spec's notes.
- **2026-10-21 — Two features merged together need a check at their seam** — #133 (reversals) merged 24 s before #135 and after #130 (audit filters). Neither PR's CI saw the other, and #133's new audit fields shipped with no EN/PL label (#145). When a PR adds audit fields, error codes or movements, test them against the screens that render them, and extend label tests to the field names.
- **2026-10-21 — Gate a commit on the real typecheck, not a piped `tsc`** — On #92, `npx tsc -p packages/app --noEmit 2>&1 | head; … && git commit` committed type errors, because the pipeline's status is `head`'s. A bare `tsc -p packages/app` also misreports a new route: `RouteContext<"/api/…">` only exists after `next typegen`, which `npm run typecheck` runs first. Run `npm run typecheck > log; echo $?` and commit only on 0.
- **2026-10-21 — A write-off has no stock movement, so transfer reversals need their own link** — `StockReversal` links movements only. A whole-document reversal that touches transit (E11-S03) records itself in an append-only `TransferReversal` per original posting, and links any physical leg through `StockReversal` as well. Don't extend a protected enum such as `TransferPosting.kind`: it rebuilds the SQLite table and changes an API value clients switch on.
- **2026-10-21 — A filter form's validation errors are not a missing page** — The #96 audit screens first sent every `VALIDATION_FAILED` to `notFound()`, a precedent from the cursor-only E02-S02 viewer. The new form's own hint invited a record ID without its type, so a normal Apply led to a bare 404. Keep not-found for page positions and cursors, and render refused filters in the form with `role="alert"` and the values as sent.
- **2026-10-21 — Reconcile net progress with immutable posting and closure history** — When lifecycle and reversal work land separately, test their combined boundary: a full inverse does not make a document unprocessed, explicitly closed lines stay non-issuable, and headers follow retained line states. During deployment overlap, include both stored Open and Completed PO lines before deriving their current progress.

- **2026-10-21 — Verify generated SQLite additions on populated data** — The lifecycle migration generator rebuilt a referenced table and copied `NULL` into its new required columns despite declared defaults. Prefer additive `ALTER TABLE` columns when possible, retain enum checks explicitly, and test populated upgrades, exact backfills and receipt foreign keys before publishing.
- **2026-10-21 — Reversal to zero does not erase posting history** — When a reversal reduces received or fulfilled quantities to zero, preserve historical identity/edit locks using immutable posting references rather than net progress alone; otherwise an old document can be reassigned after its inverse is posted. The #91 design found current customer-order guards based on `fulfilled > 0`.

- **2026-10-21 — Local integration runs share one image tag across worktrees** — `tests/integration/global-setup.ts` tags every build `cpg-integration`, so concurrent cezar sessions can make a run test another checkout's image. The #114 run saw production-order routes 404 while smoke passed. Before trusting a local failure, check `docker images cpg-integration` was created after your last commit. Also run `npm ci` in a fresh worktree first, or `@cpg/*` resolves to the main checkout's packages. When Docker is out of disk, don't prune shared state: say so and rely on CI.
- **2026-10-20 — Leave the full integration suite to CI** — The #87 run ran the 15-minute suite locally twice, then CI ran it again on the PR. CI is the gate that counts (a clean checkout, merged with `main`, and deploys depend on it), so a local full run only doubles the wait. Run the integration files the change touches locally, plus `smoke.test.ts` when a migration is added, and check the PR's CI result before calling the work done (AGENTS.md, Testing).
- **2026-10-20 — A Zod object drops unknown keys: refuse a locked field with `z.never()`** — The PO `PATCH` line schema took `{ line, plannedDate }`, so a client sending a received line's `quantity: "79"` got 200 with the field silently ignored, which is not the "refused" BUY-022/023 ask for. Declare every field an edit must refuse as `z.never({ error: … }).optional()` (as `supplier`/`location` already were), and test the 400 per field.
- **2026-10-20 — This repo has no Prettier config** — `npx prettier --write` fetches Prettier and formats at 80 columns, unlike the code around it (about 140). Don't run it with defaults; if a file needs reflowing, pass `--print-width 140` and check the diff.

- **2026-10-20 — Bind an aggregate edit to the version it opened with** — Revalidating after a conflict can replace a dialog’s order prop while its form still holds old values. Capture the order when opening the dialog and keep that version until it closes; otherwise a second Save can overwrite the concurrent change with stale fields under the newly loaded version.

- **2026-10-20 — Preserve references when replacing an operational line** — Keeping omitted customer-order lines as hidden history did not preserve a material replaced on an existing line: assigning the new material erased the old FK and unlocked its type/base unit. Archive the old allowlisted line before replacement, retain the visible stable ID, and test both removal and replacement.
- **2026-10-20 — Preserve error context through every adapter** — When adding error parameters, inspect import row issues as well as HTTP/action wrappers. Keep public message parameters through report adapters and fall back to actionable server text when a translated template lacks its context.
- **2026-10-20 — Translate dynamic refusals with structured context** — New error codes need EN/PL labels and audit IDs need display names. Send public string parameters through the shared error envelope so translations preserve exact quantities and record identifiers without parsing English messages.
- **2026-10-20 — Resolve a delegated source conflict explicitly** — When the owner directs autonomous completion after a baseline conflict is presented, record the chosen interpretation and its authority in a named decision; preserve the conflicting source as an erratum instead of silently treating it as consistent. #80 uses signed manual stock changes (D07); XLS targets remain absolute.
- **2026-10-20 — Add a sidebar icon with every navigation ID** — A new leaf in `nav-tree.ts` also needs an entry in `sidebar-nav.tsx`'s exhaustive icon registry. Without it, the sidebar fails at runtime; typecheck and the full sidebar tests catch this before publication.
- **2026-10-20 — Resolve inventory correction input semantics before defining its contract** — The #80 backlog and INV-006 describe signed manual changes, while the decision register §03 describes target balances. Compare the issue, decision register and conceptual model, and obtain the owner’s resolution before fixing either interpretation into the form or API.

- **2026-10-17 — Docker `npm ci` tries to compile better-sqlite3** — npm runs `node-gyp rebuild` because the package has a `binding.gyp`, which fails without Python/a compiler. better-sqlite3 ships prebuilt binaries (musl included), so the Dockerfile uses `npm ci --ignore-scripts`.
- **2026-10-19 — Name a function `useX` only if it is a React hook** — `react-hooks/rules-of-hooks` treats every `useX()` call as a hook, even in a plain helper or a test, and fails lint ("called in function … that is neither a component nor a hook"). That is why `useTenant` became `selectTenant`.
- **2026-10-19 — MikroORM filters and the flush don't see every write** — the `tenant` filter covers `find*`, `count`, populate, `nativeUpdate` and `nativeDelete`, and `TenantGuard` sees only flushes. These bypass both:
  - `insert`/`upsert`/`clone`;
  - the QueryBuilder: its root, `from()` with an entity or a raw table name (any case), `clone()`, and joins;
  - `getDriver()` and `addFilter()`;
  - `nativeUpdate` data with a relation key or a raw column name (MikroORM passes unknown keys through as SQL).

  The same holds for a global entity that references tenant data. `TenantEntityManager` refuses these at runtime for every entity that touches tenant data, but joins and raw SQL can't be fully checked there, so ESLint bans the QueryBuilder, the driver, `addFilter` and raw SQL in `core`/`app`. After a MikroORM upgrade, re-read the `EntityManager` write methods and run `packages/db/src/tenants/tenant-isolation.test.ts`.
- **2026-10-19 — MikroORM 7 entities can declare triggers** — `defineEntity({ triggers: [...] })` makes `db:migration:create` emit `create trigger`/`drop trigger`, and the snapshot tracks them, so a second `create` sees no drift. Prefer that to hand-written trigger SQL in a migration (the audit's append-only triggers).
- **2026-10-19 — `p.….nullable()` infers `T | null | undefined`** — an entity still held in the identity map from this request's own `em.create` has unset optional fields as `undefined`, not `null`. Map with `?? null` when a view promises `null`, and test it by reading back through the same EntityManager.
- **2026-10-19 — shadcn's generated `use-mobile` hook fails lint** — it sets state inside an effect, which `react-hooks/set-state-in-effect` rejects. `ui/src/hooks/use-mobile.ts` is rewritten on `useSyncExternalStore` (server snapshot `false`); re-apply that after a `shadcn add` that regenerates it.
- **2026-10-17 — shadcn v4 imports `cn` from the `cn` npm package** — `import { cn } from "cn"` in generated components is correct, not a broken alias. The `new-york` style is legacy; this repo uses `radix-nova`.
- **2026-10-20 — A label passed to a client component must be plain data** — making four Import strings plural-aware functions (`button: (count) => …`) passed every unit test, which render the client component directly, but the server refused the page ("Functions cannot be passed directly to Client Components"); only the integration suite showed it. Give count-dependent strings `{ one, other }` forms (`counted` in `components/imports/report-text.ts`), and test that a screen's labels hold no function (`components/imports/labels.test.ts`).
- **2026-10-19 — A client component must not import a module that imports `@cpg/core`** — `nav-menu.tsx` (`"use client"`) imported one helper from `nav-items.ts`, which imports `TENANT_NAMES` from `@cpg/core`, and the browser bundle pulled in the ORM. Lint, typecheck and unit tests all passed; only `npm run build` failed ("Module not found … [Client Component Browser]"). Keep what client code needs in dependency-free modules (`components/layout/current-path.ts`), or import a `@cpg/core/validators/*` subpath, and build before pushing.
- **2026-10-19 — Docker Desktop can belong to another macOS user** — Docker Desktop was running as `piotrekhl`, so this account had no `~/.docker/run/docker.sock`, and `open -a Docker` doesn't help. Don't touch the other session. Run the image's server without Docker instead, then `CPG_BASE_URL=… npm run test:integration`:
  - copy `.next/standalone`, add `.next/static` under `packages/app/.next/` and `packages/app/public` beside `server.js` (otherwise manifest icons 404), and start `node packages/app/server.js` with a temp `DATA_DIR` and `CPG_ADMIN_PASSWORD`;
  - not `next start`, which warns it doesn't support `output: standalone`. Under it, a soft navigation to `/admin/test` after a signed-out visit intermittently rendered a 404 that the standalone server never showed in two full runs.

  The Docker-only test (`startup-guard`) is skipped, and CI covers the image.

- **2026-10-20 — Never name a zsh variable `path`** — in zsh, `path` is tied to `PATH`, so `path="spec-boms/x.png"` in a loop wiped the command path and every later command failed with "command not found" (the evidence upload of #69). Use another name (`rel`, `file`).
- **2026-10-20 — Open an outer savepoint on the request `em`, never with `em.transactional()`** — `em.transactional()` on the request `em` puts its savepoint on a fork. Services keep using the request `em`, so their own savepoints take the same name (`trx1`), and MikroORM rolls a savepoint back without releasing it. After one refused service call, a later `ROLLBACK TO` lands on the wrong savepoint, and earlier writes survive a "rolled back" dry run. A fresh-context spec review reproduced it. Use `inRequestSavepoint` (`core/src/http/request-transaction.ts`): it opens the savepoint with `em.begin({ ctx })` on the request `em`, restores the request transaction and clears the identity map.
- **2026-10-20 — Clear the identity map between rows of a bulk run** — the import ran 2,000 rows through the services in one transaction, and every flush walked an identity map that grew with every row: 17.9 s in Docker. Clearing the map after each row (everything is already flushed) made it 0.4 s. Any loop of service calls in one request needs the same (`runRow` in `services/imports/apply-context.ts`).
- **2026-10-20 — One big posting is a bulk run too: post it in chunks** — the stock import's commit sent 2,000 lines to `postStockMovements` in one call. Each line's lookups auto-flush, and each flush walked every movement, balance and audit entry created so far: 23.5 s. One posting ID, flushed in chunks of 25 with `em.clear()` between them (`firstPosition` keeps the positions unique), took 1.2 s. Measure a bulk write at its row cap before shipping it (`StockImportService.commit`).
- **2026-10-20 — Bound an uploaded spreadsheet by the cells it spans, not only by its bytes** — `read-excel-file` pads every row out to the last filled column and adds an empty row for every gap. So a 1.4 KB workbook with one cell at `XFD10000`, or one empty `<row r="30000000"/>`, ran the server out of memory, and the 512 KB and 20 MB inflate limits never fired. `readWorkbook` now refuses more than 200,000 spanned cells before the reader runs (`cellsSpanned` in `components/imports/workbook-file.ts`). Such a pre-check must read addresses the way the library does: namespace prefixes, character references, `Number()` on row numbers, `>` inside quoted values. Each disguise needs a test.
- **2026-10-20 — Never take the rest of an Awilix PROXY cradle** — `constructor({ em, tenant, ...services })` enumerates the whole cradle, resolving every registration, the service itself included: "Cyclic dependencies detected". Destructure each dependency by name.
- **2026-10-20 — `z.flattenError` keys a field error by the first path segment only** — a list item's error (`components.2.unit`) came back as `components`, so a form couldn't put it on its row. `validationError` (`core/src/http/parse-input.ts`) now keys by the full dotted path; top-level fields keep their plain names.
- **2026-10-20 — The sidebar must fit 1280×800 without scrolling** — a Procurement group (header + two entries) pushed "Audit" below the scroll edge of `sidebar-content`, so `navigation.test.ts` ("every screen … one click away") couldn't click it ("covered by div.flex.h-8"). Unit tests passed. Add tenant entries flat, not as a new group, or shorten something else, and run `navigation.test.ts` after any nav change.
- **2026-10-20 — Standalone integration runs need `static` and `public` copied** — besides `.next/static` into `packages/app/.next/`, copy `packages/app/public` next to `server.js`, or `app-icons.test.ts` gets 404s. Run each full pass on a fresh `DATA_DIR`: files leave users and tokens behind, and a rerun on the old data fails in `beforeAll`.

- **2026-10-21 — Order report rows by business ID, never by the UUID a reference holds** — the stock report first tallied pairs by `balance.material.id`, the internal UUID, so its "by material, then location" order was random. Only a test with more pairs than a page caught it: the small fixtures happened to sort the same both ways. Map references to their `code` before sorting or paging, and test ordering with enough rows for UUID and code order to differ. The test also has to reach the sort out of order: SQLite returns an unordered `find` (`$in` included) in insertion order, which for sequential IDs already looks sorted, so the #95 variance report only covered both comparator branches once it fed the sort in the completions' UUID order.
- **2026-10-21 — The tenant-filter lint rule also fires on a React prop named `filters`** — `no-restricted-syntax` bans any `filters` property in `core`/`app`, to keep MikroORM's tenant filter on, and it can't tell a component prop from a find option. Name report or list filter props something else (`selected`), and don't disable the rule.

## Testing

- **2026-10-21 — Find an icon button by its `aria-label`, not its text** — the row ⋯ menu's name ("Actions for 00000005") is only an `aria-label`, so a `button()` helper that matched `textContent` waited forever in the #141 UI test. Copy the helper from `named-records.test.ts`, which matches either.
- **2026-10-21 — `element.querySelectorAll("tbody tr")` also matches through the element's ancestors** — a selector is matched against the whole document, and only the result is limited to the element's descendants. On the variance report, a nested component table inside a `DataTable` cell returned its own header row, because the cell itself sits in the outer `tbody`. Prefix the selector with `:scope` (`cell.querySelectorAll(":scope tbody tr")`) when reading a table inside a table.
- **2026-10-21 — agent-browser writes a relative screenshot path under its daemon's directory** — the #89 QA run's `screenshot .ai/qa/…/01.png` reported success but nothing appeared in the worktree. Always pass an absolute path to `agent-browser screenshot`, and `ls` the folder afterwards.
- **2026-10-21 — agent-browser clicks where it measured, so wait for the layout to settle** — on a signed-out page the visitor bar streams in late and moves the login card; under load that happens after hydration, so the submit click hit the form and TEN-006 timed out with nothing sent (#128). Before clicking, wait for the last streamed layout change as well as hydration (`signedOutLayoutSettled` in `tests/integration/sign-in.ts`). [details](lessons/2026-10-21--1007UTC-late-layout-shift-lost-click.md)
- **2026-10-21 — The standalone server shares one sign-in throttle bucket across test browsers** — it sets `X-Forwarded-For` itself, so a long local probe that exceeds 50 failed sign-ins in 15 minutes gets "Too many attempts" everywhere. Restart it between long runs (stop it by port, see below).
- **2026-10-21 — The shadcn checkbox needs `ResizeObserver`, which jsdom lacks** — inside a form, Radix's checkbox measures its hidden input, and the first component test with one failed with "ResizeObserver is not defined". `tests/setup/dom.ts` now stubs a no-op one; don't add another stub per test.
- **2026-10-21 — Stop a standalone test server by its port** — `pkill -f "<copy>/packages/app/server.js"` matched nothing, because the server runs as `node packages/app/server.js` from its copy's directory, so the old build kept answering. Kill `lsof -t -iTCP:<port> -sTCP:LISTEN` and check the port is free before starting the next copy.

- **2026-10-20 — Wait for client-applied `<html>` state after a soft navigation** — `preferences.test.ts` read `lang` and the `dark` class right after signing in; the Polish heading was already rendered but `DocumentPreferences` had not yet updated the root `<html>`, which a soft navigation keeps. It failed once in CI (#110) after passing elsewhere. `waitUntil` the document attributes before asserting them.

- **2026-10-20 — Wait for a dialog’s overlay before clicking behind it** — A cancelled shadcn dialog leaves its fading overlay for 100 ms. Wait until both `[role=dialog]` and `[data-slot=dialog-overlay]` are gone before clicking the page’s Edit button; checking hydration alone can still click the overlay.

- **2026-10-20 — Start each standalone build from a fresh copy** — Overlaying a new `.next/standalone` onto a running test copy retained `.next/server/route-cache` from the previous build. Prod then loaded an old dialog chunk while Test loaded the fix. Copy standalone, static and public into a new empty directory on every rebuild; a fresh database alone does not clear Next’s runtime route cache.
- **2026-10-20 — Use an untouched standalone copy for each macOS integration run** — Next stores route caches by pathname. The negative `/admin/TEST` test writes a 404 to the same cache file as `/admin/test` on case-insensitive APFS, so reusing that standalone directory can break later valid soft navigation even with a fresh `DATA_DIR`. Copy the complete pristine build into a new runtime directory for each run; retain the uppercase rejection test, and use Linux/Docker for image validation.

- **2026-10-20 — Hash preview generations inside the write transaction** — A tenant scope captures metadata before the transaction. A request scoped before a reset could accept a new generation header but hash the old captured generation, allowing a pre-reset import preview to commit against reseeded IDs. Read `TenantService.currentState` inside the apply transaction; test equal fixtures across a real reset and prove the test fails with the captured generation.
- **2026-10-20 — Copy public assets before starting standalone QA** — The documented Docker fallback needs both `.next/static` and `packages/app/public` in the standalone app directory. Copy them before startup: Next.js caches the public-file inventory, so copying them into an already running server still returns 404 until it restarts.
- **2026-10-20 — Standalone test copies need public assets, and login needs hydration** — Copy `packages/app/public` as well as `.next/static` into the standalone runtime; otherwise manifest icons return 404. Wait for the login input's React fiber before filling/submitting, as for other hydrated controls. Hydration alone did not stop the post-reset sign-in timeout: see the 2026-10-21 lesson on late layout shifts (#128).

- **2026-10-17 — Root-level config files are `.mts`** — the root `package.json` has no `"type"`, so Vite loads `vitest.config.ts` as CommonJS and warns. Name root-level ESM files `.mts` (`vitest.config.mts`, `vitest.integration.config.mts`). Root tests (`tests/*.test.ts`) run through Vitest, so `.ts` is fine there.
- **2026-10-17 — `tmpdir()` can be inside the repo** — cezar points `TMPDIR` at `.ai/cezar/tmp/…`, so a temp dir has the monorepo as an ancestor. Don't assume a temp dir is outside the workspace; use the filesystem root when a test needs "no workspace above me".
- **2026-10-19 — `migrator.down({ to })` keeps `to` applied** — it rolls back only the migrations after the named one. A test that meant "roll back the materials migration" with `down({ to: "…_materials" })` left the materials tables in place once a newer migration existed. Call `down()` once per migration, newest first (`packages/db/src/orm.test.ts`), and a new migration has to update the older migrations' rollback tests.
- **2026-10-17 — Don't run MikroORM migrator calls concurrently** — `getExecuted()` and `getPending()` each create `mikro_orm_migrations` if missing, and under `Promise.all` on a never-migrated database the second one fails with "table already exists". Await them one after the other (there is one SQLite connection anyway).
- **2026-10-17 — React DOM can't render async server components** — React suspends forever on them and Testing Library only shows the `<Suspense>` fallback. Call the page function and await its async children before `render()` (`resolveServerComponents` in `app/src/app/admin/page.test.tsx`).
- **2026-10-17 — Testcontainers `withBuildkit()` fails on this repo** — the build stops with "failed to read dockerfile: archive/tar: invalid tar header". The default (classic) builder builds the Dockerfile fine; `tests/integration/global-setup.ts` uses it.
- **2026-10-19 — `agent-browser wait --fn` needs a boolean** — an expression that returns a DOM element (`document.querySelector(…) || …`) fails with "CDP error: Object reference chain is too long". Wrap it: `!!document.querySelector(…)`.
- **2026-10-19 — React 19: updates after `await` leave the transition** — inside `startTransition(async () => { await x; setState(…) })` the `setState` commits outside the transition, so an error can show while `isPending` is still true (a flaky "button still says Saving…" test). Wrap post-await updates in another `startTransition` (see `ui/src/backend/forms/crud-form.tsx`).
- **2026-10-17 — Reading output from agent-browser** — `get text`/`get title` print plain text, but `eval` prints pretty-printed JSON or a quoted string. Use `--json eval` and read `.data.result` (the `evaluate()` helper in `tests/integration/browser.ts`). Give each test its own `--session` so parallel tests never share a page.

- **2026-10-19 — Integration test files share one admin account** — every file signs in as the single built-in admin, so a file that changes the admin's language or theme leaked into files running beside it. `vitest.integration.config.mts` runs files one at a time (`fileParallelism: false`), and a file that changes preferences restores them in `afterAll` (`restoreDefaultPreferences`). Revisit once E01-S02 lets a file create its own account.
- **2026-10-19 — shadcn table cells never wrap** — `TableCell` is `whitespace-nowrap` inside an `overflow-x-auto` box, so a long free-text value (a 64-character token name) or a full timestamp widens the row and pushes the row actions off-screen; at 390 px it happened with any name. Give unbounded columns `whitespace-normal` (`wrap-anywhere` for names), hide secondary columns below `sm`, and assert in a real browser that row actions stay in view (`tests/integration/api-tokens.test.ts`, `setViewport`).
- **2026-10-19 — Integration test files share one database** — a file's users (never deleted) and settings stay for every file after it. `api-tokens.test.ts` broke `users.test.ts` (full-table assertions, `waitForText("Inactive")` satisfied by another file's user) and `smoke.test.ts` (the startup admin-password stamp is a setting). Scope assertions to the records the file created (`aliceRow` in `users.test.ts`), and give each file its own usernames.
- **2026-10-19 — A cezar worktree may have no `node_modules` of its own** — Node then resolves `@cpg/*` to the main checkout's `node_modules`, whose workspace links point at the main checkout's packages: tests and typecheck run the wrong code. Run `npm ci` in the worktree before the first test.
- **2026-10-19 — better-sqlite3 waits for a lock synchronously** — a second connection that hits SQLite's write lock busy-waits in C, blocking Node's event loop, so the holder can't finish and both stall until `busy_timeout` ("database is locked"). Every Next.js bundle has its own connection in one process. Never hold the write lock across real async work (argon2, I/O): read first, write last (`IdempotencyService.run`). A test racing two ORMs in one process shows it.
- **2026-10-19 — `em.transactional()` on a request fork doesn't reach the services** — forks have `useContext = false`, so the transaction lives on a child fork, and a service holding the request `em` starts its own top-level transaction, which waits forever for the single Kysely connection. Open the transaction on the request `em` itself with `em.begin()`/`commit()` (`inRequestTransaction`); services' `flush()` and `transactional()` then join it as savepoints.
- **2026-10-19 — Same-millisecond audit entries sort by their random id** — `orderBy: { occurredAt, id }` puts two entries written in one millisecond in random order. A test that writes them back to back flaked (`api-token.service.test.ts`). Separate them in time, or assert without order.

## Next.js

- **2026-10-17 — Kill the whole server before runtime checks** — `pkill -f "next start"` misses the `next-server` child it spawns, which keeps the port, so later curl checks silently hit the old build. Check `lsof -nP -iTCP:<port> -sTCP:LISTEN` is empty before starting a server and after stopping it.
- **2026-10-17 — Patterns from pre-Cache-Components projects don't transfer as-is** — `export const dynamic = "force-dynamic"` no longer exists (use `await connection()` + `<Suspense>`), and server components must not fetch the app's own `/api` routes (Next.js docs: extra request). - **2026-10-17 — One ORM per bundle, keyed by entity identity** — Next.js gives route handlers, pages and instrumentation separate copies of `@cpg/db`, and MikroORM matches entities by object identity. Never cache the container/ORM on `globalThis` under a string key; `getContainer()` (in `@cpg/core`) keys it by the `entities` array. [details](lessons/2026-10-17--0920UTC-mikroorm-entity-identity-next-bundles.md)
- **2026-10-17 — Next.js 16 icon `<link>`s differ from its docs** — `app-icons.md` says `favicon.ico` gets `sizes="any"`, but the build emits the ICO's largest image (`sizes="48x48"`) and a content-hash query on every icon `href`. - **2026-10-19 — The standalone server doesn't exit when `register()` throws** — `node server.js` (the Docker image) logs "Failed to prepare server" and answers every request with a 500. Only `next start` exits. - **2026-10-19 — With Partial Prefetching, `notFound()` on an unlisted dynamic param answers HTTP 200** — since Next 16.3, a param missing from `generateStaticParams` gets the route's App Shell first, so the layout's `notFound()` streams the 404 UI with `<meta name="robots" content="noindex">` and can't change the status (`streaming.md`, "The HTTP contract").
  - `dynamicParams` is unavailable under Cache Components.
  - `ensureStatic = 'navigation'` forbids `connection()` and DB reads.
  - Test the not-found UI and `noindex`, not the status code (`tests/integration/tenants.test.ts`). Route handlers still answer real 404s.
- **2026-10-19 — Moving a page into a route group can trip `no-html-link-for-pages` elsewhere** — once `/admin` lived under `admin/(global)/`, the rule started flagging a `<a href="/admin">` in a `ui` package test. Use external URLs in tests of generic link components.
- **2026-10-20 — A `catch` that logs must let Next.js's control-flow errors through** — under Cache Components, `npm run build` prerenders every `GET` route handler. Reading `request.headers` or `cookies()` stops the prerender by throwing (`NEXT_PRERENDER_INTERRUPTED`, `HANGING_PROMISE_REJECTION`), and the shared `apiHandler` caught that and logged "Route handler failed" on every build (#38). `redirect()` and `notFound()` throw the same way. Call `unstable_rethrow(error)` first in a catch-all around route handlers or code that reads request data while rendering (`serverAction` needs none: actions are never prerendered, and redirects happen in the caller); `core` can't import `next`, so it takes the function as a parameter (`createApiHandler`, wired in `app/src/routing/api-handler.ts`). `await connection()` doesn't help: it rejects the same way.
- **2026-10-17 — Dynamic `fs` paths make Turbopack trace the whole project** — paths built from env/`process.cwd()` pull every source file into the standalone output. Mark them with `/* turbopackIgnore: true */` (see `packages/core/src/config.ts`).

- **2026-10-19 — Revalidate the exact page, never a layout over dynamic tenant pages** — `revalidatePath("/admin", "layout")` after the read-only toggle made Next.js regenerate every static shell under `/admin` at runtime. The `/admin/[tenant]` shells (`generateStaticParams`, data behind `connection()` in `<Suspense>`) then failed with "encountered uncached or runtime data during prerendering" (`NEXT_STATIC_GEN_BAILOUT`), and every later request to them hung. Lint, unit tests and the build all passed; only the integration suite caught it. Revalidate the page that shows the change (`revalidatePath("/admin")`). Pages that read at request time need no revalidation.
- **2026-10-19 — A refresh after a refused write can hide its explanation** — revalidating the materials page after `TENANT_READ_ONLY` re-rendered it without the controls, which unmounted the dialog and its error, so the user saw the dialog vanish without a reason. Refresh after a refusal only when the controls that showed the error survive it (`VERSION_CONFLICT` does, a read-only refusal doesn't).

- **2026-10-20 — A server action must pass on the field errors a service throws** — `serverAction` kept `fieldErrors` only for its own parse errors, so a `ValidationError` from a service (Make on a raw material, a rule only the service can check) reached the form as "Some fields are invalid." with nothing beside the field.
